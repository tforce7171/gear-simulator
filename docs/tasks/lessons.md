# 知見の候補

自動実行（`.claude/workflows/implement-all.js`）の担当が、作業中に得た知見をタスクごとに貯める。実行の最後に retro スキル（`.claude/skills/retro/SKILL.md`）がこれを読み、CLAUDE.md・スキル・design.md などに反映して、各項目の状態を書き換える。

ここに書くのは、**次に別のタスクをする担当が知っていれば、速く・確実に済んだこと**。タスク固有の仕様の判断（仮定）は [implementation-log.md](implementation-log.md)、人が手で確かめる項目は [manual-checks.md](manual-checks.md) に書く。

## 書き方

タスクごとに `### <ID> <題名>` の見出しを末尾に足し、その下に 1 項目 1 行の箇条書きで書く（同じタスクをやり直したときは見出しをもう一度足す）。

```
### S5-03 カメラの注視点を部品に合わせる
- [未還元] 〔探し直した事実〕e2e で歯車の画面座標を出す部品は sim.ts の gearScreenPoint。根拠: impl が 3 回 grep し直した
- [未還元] 〔レビューの指摘〕時間に依る spec を --repeat-each=5 で流していなかった。根拠: review#1 で不合格
```

- **種類**: 〔探し直した事実〕〔詰まったこと〕〔落とし穴〕〔レビューの指摘〕のどれか。
- **内容**: 1〜3 文。ファイル・関数・コマンドの名前を入れる。
- **根拠**: 回数・不合格の回・関わったファイルやコマンド。
- **状態**（行頭の `[...]`）:
  - `[未還元]`: まだ retro が見ていない。
  - `[還元済み <ブランチ名>]`: その retro のブランチで反映した。
  - `[既出]`: CLAUDE.md・スキル・design.md などに既に書いてある。
  - `[陳腐化]`: 今の main では起きない。
  - `[見送り n/3 <理由>]`: 今回は反映しなかった。retro のたびに検討し直し、3 回目の見送りで `[却下 <理由>]` にする。

同じタスクの impl とレビューが同じことを言っていれば 1 項目にまとめる。
