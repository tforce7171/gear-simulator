# S2-02 かさ歯車

## 目的
交わる 2 軸の間で回転を伝えるかさ歯車を入れる。軸の向きを 90° 曲げられるようになり、縦・横 X・横 Z の 3 方向を行き来する機構が作れる。

## 範囲
- **決めた値**
  - 交わる角度は 90° のみ（要件 §3.1）。軸は 3 方向のままで閉じる
  - **歯数比は 1:1（マイタ歯車）のみ**。ピッチ円すい角は両方とも 45° に固定する
    - 理由: 形状が相手の歯数によらず `(大きさ, 歯数)` だけで決まる。偶然のかみ合いの判定も単純になる。速度を変えたいときは、同じシャフトの平歯車で変える
  - かさ歯車の歯数を変えると、木の親子のかさ歯車のかみ合いでつながったかさ歯車すべての歯数が同じ値に変わる（1 つの編集コマンド、Undo 1 回）
  - 大きさ・歯数の範囲は平歯車と同じ。歯の幅 b は `min(大きさの歯幅, 円すい距離 / 3)`（円すい距離 = `R·√2`、R は大端のピッチ円半径 `m·z/2`）。b は円すいの母線に沿った長さで、軸方向には `b·cos45°` を占める
- **向き** `apex: 1 | -1`: ピッチ円すいの頂点が、大端のピッチ円の中心から見てシャフトの軸の正・負のどちらにあるか
- **軸方向の位置**（design.md §4 の `offset` に合わせる）
  - かさ歯車も、大きさの歯幅（中なら 8）の区画を占めるものとして扱う。`offset` はその区画の負側の面の位置（AXIAL_SNAP の倍数）、中心は §4 の式どおり `原点 + (offset + 歯幅/2)·軸`
  - **大端の中心**（大端のピッチ円の中心）は、区画の頂点と反対側の面: `大端の中心 = 中心 − apex·(歯幅/2)·軸の単位ベクトル`。歯は大端から頂点の側へ伸び、軸方向の `b·cos45°` は歯幅より小さいので区画からはみ出さない
  - 頂点 = `大端の中心 + R·apex·軸の単位ベクトル`
  - `apex` を反転すると、区画（`offset`）はそのままで、大端が区画の反対の面に移る
- **新しい配置** `ShaftPlacement` の `'bevel'`
  ```ts
  | {
      readonly kind: 'bevel';
      readonly parentGearId: GearId; // 親のかさ歯車
      readonly childGearId: GearId;  // このシャフト上の、親とかみ合うかさ歯車
      readonly axisStep: 1 | 2;      // このシャフトの軸 = 親の軸を x → y → z → x の順に axisStep 回進めた軸
      readonly side: 1 | -1;         // 子が、親の大端の中心から見てこのシャフトの軸の正・負どちら側にあるか
    }
  ```
  - `axis` は持たない（design.md §4。`root`・`detached` 以外の配置は向きを親から導く）。このシャフトの軸は `axisStep` で親の軸から決まり、`Layout.shafts[id].axis` に出す。親の向きが R で変わっても、子は親との相対の関係を保ってついてくる
  - 軸を進める関数（`stepAxis(axis, step)`）は S2-03 の `'skew'` でも同じものを使う。`core/math` などに 1 つだけ置く
  - `axisStep` 2 通り × `side` 2 通りで、親 1 枚につき 4 か所
  - 子の大端の中心 = `親の大端の中心 + R·side·(このシャフトの軸の単位ベクトル) + R·親の apex·(親の軸の単位ベクトル)`。子の `apex` は `-side`（親の頂点を向く）。2 枚の頂点は一致する
  - 子の `offset` は 0 として、シャフトの原点を逆算する（`mesh` と同じ考え方）。子の大端の中心 = `原点 + (歯幅/2)·(1 + side)·軸の単位ベクトル` になる
  - 位置は 4 か所の離散なので、外周の角度の円弧ハンドルは出さない
- **候補**: かさ歯車を選ぶと、上の 4 か所のうち干渉しないものを候補に出す。子は同じ大きさ・同じ歯数のかさ歯車。同じ軸の候補は、作る種類にかさ歯車を渡せるようにする（S2-01 で足した引数）
- **偶然のかみ合い（contact）**: どちらもかさ歯車、同じ大きさ・同じ歯数、軸が直交、頂点の距離が `MESH_DISTANCE_EPS` 以内。頂点が一致すればピッチ円すいは必ず接する
- **位相**: 2 つのピッチ円の接点 P で、親の歯の中心と子の歯溝の中心が重なるように子の `basePhase` を決める。contact は段階 1 と同じく位相を問わず拘束として扱い、干渉にはしない（§5）
- **運動学**: かさ歯車の組の拘束は
  ```
  apex_a·z_a·ω_a + apex_b·z_b·ω_b = 0
  ```
  （ω は各シャフトの軸の正の向きまわり。ピッチ点 P での周速の一致 `ω_a·(e_a × (P − c_a)) = ω_b·(e_b × (P − c_b))` から導いた式で、親の向き・子の軸・side の 24 通りすべてで成り立つことを確認済み）
  - かみ合いの拘束を種類で分岐するのでなく、「かみ合い 1 組 → 2 つの係数」を返す関数にまとめると、後続（S2-03、S2-04、S3-02、S3-03）で足しやすい
- **干渉判定**: かさ歯車を、歯のある円すい台に外接する円柱で近似する。円柱は大端の中心から頂点の側へ `b·cos45°` の長さ、半径は `R + m·cos45°`（大端の歯先）。かみ合っている組同士は、平歯車と同じく干渉判定から除く
  - 頂点の側にシャフトを伸ばすと相手のシャフトと交わる（本物でもぶつかる）。これは線分同士の干渉としてそのまま赤く出す
  - **シャフトの頂点側の端**（決定）: 余白込みのシャフトの端は大端から `歯幅 + SHAFT_END_MARGIN` になり、小の 12〜15 歯（R = 6〜7.5）では頂点を越え、小の 16 歯（R = 8）と中の 12 歯（R = 12）ではちょうど頂点に届く。そこで、かさ歯車が載るシャフトは、頂点側の端を `頂点 − BEVEL_APEX_CLEARANCE·apex·軸`（`BEVEL_APEX_CLEARANCE = 2` mm）で切る。ただし、同じシャフトの頂点側にほかの部品が載っていて、その部品がこの位置を越える場合は、その部品の面 + `SHAFT_END_MARGIN` まで伸ばす（相手のシャフトと交われば干渉として赤く出る）
  - 切ったあとのシャフトの端が、かさ歯車自身の区画の内側に入ってもよい（歯は大端から頂点に向かって `b·cos45°` しか伸びないので、見た目は破綻しない）
- **形状**: 大端の断面は歯数 z の平歯車のインボリュート歯形（簡略化。相当平歯車の歯数は使わない）。これを頂点に向かって相似に縮めながら、ピッチ円すいに沿って歯幅の分だけ押し出す。背面（大端側）は平らな円板で閉じる
- **表示**: 段階 1 と同じ材質。形状データのキーは `(種類, 大きさ, 歯数)`（`apex` は向きの回転で表すので形状には含めない）
- **保存**: シーンの検証で `'bevel'` の歯車・配置を受け付ける（子の `apex === -side`、子のシャフトの軸が親と違うことも検証する）。`version` は 1 のまま
- **S2-01 の時点**: 歯車の種類を足すと、`switch (gear.kind)` の `assertNever` でコンパイルエラーになる所（`src/core/scene/gear-shape.ts` の `gearShape`・`newGearShape`・`meshPartnerShape`・`GEAR_KINDS`、`geometry/can-mesh.ts` の `canMesh`・`meshKindOf`、`geometry/shape-key.ts` の `gearShapeKey`、`scene/parse.ts`、`render/gear-geometry.ts` の `buildGeometry`）を直す（design.md §4）。`MeshKind` は `geometry/can-mesh.ts` にある。候補（`GrowCandidate`）は作る歯車の形 `shape: GearShape` を持ち、同じ軸の種類は `GrowSpec.coaxialKind`（app は今 `'spur'` を渡す。`src/app/interactions.ts`）、編集コマンドの種類は `addRootShaft` の `gear.kind?`・`growGear`（coaxial）の `kind?` で渡す。外周に生やす子の形は `meshPartnerShape` で決まる
