# S1-21 手で回す

## 目的
歯車をつかんで手で回し、つながった歯車が歯数比どおりに動くのを確かめられるようにする（要件 §5「手で回す」、§7.1）。手の力は無限に強く、歯車群は手の位置に完全に追従し、離すと即座にモーター同士のつり合いの速度に戻る。

## 範囲
- **入力**
  - 歯車（またはシャフト・モーター。同じ剛体なので）の上で、修飾キーなしの左ボタンを押し、`DRAG_THRESHOLD_PX` 以上動かしたら手で回し始める。動かさずに離したら、これまでどおり選択（S1-16）（S1-16 では、クリックは `src/input/selection-input.ts` がカメラの経路と別に受けている。手で回すは `'app'` の経路のポインターの、しきい値を超えたドラッグだけを扱えばよい。`selection-input` はしきい値を超えたらクリックにしないので、ドラッグで選択は変わらない）
  - ただし、選んでいる `detached` のシャフト（またはその上の歯車・モーター）の本体のドラッグは、S1-19 の付け直しのドラッグを優先する（選んでいなければ手で回す）
  - 回す基準は、ボタンを押した位置の角度（しきい値を越えた位置ではない）。回し始めに飛ばない
  - ポインターをキャプチャし、描画領域の外へ出ても離すまで続ける。`pointerup`・`pointercancel`・Esc で終える（回している最中の Esc は回すのを終えるだけで、選択は外さない）
  - 手の角度: ポインターのレイと「つかんだ歯車の中心を通り、軸に垂直な面」との交点の、軸まわりの角度。面を真横から見ていてレイがほぼ平行（レイの向きと軸の内積の絶対値が 0.1 未満）なら、歯車の中心を画面に投影した点のまわりの、ポインターの画面上の角度で代用する（軸がカメラから遠ざかる向きなら符号を反転）
  - 目標の角度 = 押したときのシャフトの角度 + 手の角度の変化量の積算（毎回 −π〜π に巻き戻して足す）
  - 選択は変えない。回している間は候補（S1-18）とハンドルを隠し、カーソルを `grabbing` にする
  - 回している間の手の拘束は `AppState.sim.hand: HandConstraint | null` に持つ（design.md §7。保存しない、Undo の対象にしない）
- **運動**（design.md §6「手で回す」）
  - 手で回している間、つかんだシャフトの角度は毎フレーム目標の角度に一致する（追従の遅れなし）
  - 同じ連結成分のシャフトは、かみ合いの拘束どおり（`θ = N q`）に動く。外歯車同士なら `z_a·Δθ_a + z_b·Δθ_b = 0`
  - その連結成分の `omegas` は、前のフレームからの角度の変化 ÷ 経過時間にする（音 S1-25 と情報表示 S1-23 が使う）
  - その連結成分のモーターのうち、手の動きと逆に回されているもの（`direction × ω < 0`）は `backDriven` に入れる
  - ほかの連結成分は、これまでどおりモーターで回る
  - 一時停止中（S1-22）でも手で回せる
  - 自由度が 2 以上の連結成分（段階 3 の遊星歯車）では、つかんだシャフトの速度を拘束として足し、残りの自由度はモーターのつり合いで解く。段階 1 では自由度は 0 か 1 しか出ないので、この場合のテストは段階 3（S3-03）で足す
- **離したとき**: 角度はそのまま（戻さない）。次のフレームから、つり合いの解の速度で回る（モーターが無ければ止まる）
- **ロック中の連結成分をつかんだときの扱い**（このタスクで決める）
  | ロックの理由 | 手で回すと |
  |---|---|
  | `contradiction`（回転条件の矛盾。自由度 0。三角形のかみ合いなど） | 回らない（角度は変わらない）。ロックの表示（S1-22）はそのまま。ポインターはつかんだ扱いにし、カメラは回さない |
  | `stalemate`（逆向きのモーターのつり合い。自由度 1 で ω = 0） | 回る（手は無限に強い）。回している間はその連結成分をロックとしない（`locks` から外す）。離すと再びロックになる |
  | 段階 2 以降の理由（ウォームの逆駆動、ラックの端、固定具） | 段階 2・3 の各タスクで決める |

## 範囲外
- ロックの赤い表示と震え、一時停止そのもの（S1-22）
- 手で回したときの音（S1-25）
- 慣性（要件 §14。投げるように回して惰性で回り続ける動きは作らない）

## 作るもの
- S1-07 の `stepMotion` の `opts.hand` を使う（design.md §6。手の拘束の解き方は S1-07 で作ってある）
  ```ts
  interface HandConstraint { shaftId: ShaftId; angle: number } // 目標の角度（rad）
  function stepMotion(
    scene: Scene, layout: Layout, prev: MotionState, dt: number,
    opts?: { paused?: boolean; hand?: HandConstraint },
  ): MotionState;
  ```
  - 毎フレーム `opts` に `{ paused: sim.paused, hand: sim.hand }` を渡す。上の「運動」と「ロック中の扱い」の振る舞いが満たされていなければ、S1-07 の純粋関数を直す
  - S1-07 の時点で `src/app/loop.ts` の `runFrame` は `stepMotion(scene, layout, motion, dt)` を `opts` 無しで呼んでいる。ここに `opts` を足す（`hand` が `null` なら渡さない）。拘束の解法（`θ = N q`、ω = 角度の変化 / dt、`backDriven`、ロック中の扱い）は S1-07 の `stepMotion` に実装とテストがある（`src/core/kinematics/motion.test.ts`）。上の Vitest のうち同じ内容のものは、そちらで足りていれば足さなくてよい
  - `HandConstraint` の型は `src/core/kinematics/types.ts`、`MotionOptions` は `src/core/kinematics/motion.ts` にある
- `src/input/handle-math.ts` の `angleAroundAxis` と `unwrapDelta`（S1-19 と共用。S1-19 が先に作っていればそれを使い、無ければここで作る。仕様は S1-19 の資料のとおり）
- `src/input/hand-rotate.ts`: ポインターから目標の角度を求めて、毎フレーム運動の更新へ渡す
- `__gearSim` に追加（design.md §10 も更新する）
  ```ts
  getHand(): HandConstraint | null; // 手で回していなければ null
  ```
- `e2e/fixtures/lock-opposed.json`: `two-gears.json` と同じ 2 枚（中・20 歯）の両方のシャフトに、小のモーター（60 rpm、`direction: 1`、ON）。逆向きの等しい力でつり合って `stalemate` のロックになる。S1-22・S1-26 が先に作っていればそれを使う
- `e2e/fixtures/lock-triangle.json`: 縦軸の起点の歯車 A（中・20 歯、小のモーター 60 rpm・`direction: 1`・ON）に、外周の子 B（`angle` 0）と C（`angle` π/3）。どれも中・20 歯で、一辺 40 の正三角形になる。B と C は偶然のかみ合い（contact）で、位相を問わず拘束になるので（design.md §5）、読み込むと `contradiction` のロックになる。S1-22 が先に作っていればそれを使う

## 受け入れ条件
- [ ] 歯車の上の左ドラッグで、その歯車が手の動きに遅れなくついて回り、つながった歯車が歯数比どおりに回る
- [ ] クリック（動かさない）は選択のまま。Alt+左ドラッグはカメラの回転のまま
- [ ] 離すと、モーターのつり合いの速度にすぐ戻る
- [ ] ロック中の連結成分をつかんだときは、上の表のとおりになる

## テストケース
### Vitest（`stepMotion` など）
- [ ] 2 枚（20 歯と 40 歯、モーター無し）。手で 20 歯側を目標 +π/2 にする → 20 歯側の角度が π/2、40 歯側が −π/4。ω は（角度の変化 / dt）
- [ ] 同じシーンで、手の目標を毎ステップ少しずつ変える（10 ステップで 0 → π）→ 各ステップで、つかんだシャフトの角度が目標に一致する（`toBeCloseTo`）
- [ ] モーター付き（`direction: 1`）のシャフトを手で負の向きに回す → `backDriven` にそのモーターが入る。正の向きなら入らない
- [ ] 手で回している連結成分とは別の連結成分のモーターは、手の有無で ω が変わらない
- [ ] 手を外した次のステップ → ω がつり合いの解（モーター 1 つなら無負荷回転数）に戻り、角度は手を外す直前から続く
- [ ] 逆向きのモーターでロックしたシーン（`stalemate`）→ 手で回すと角度が変わり、`locks` が空。手を外すと `locks` に `stalemate` が戻る
- [ ] 三角形のロック（`lock-triangle.json` と同じシーン。自由度 0）→ 手の目標を変えても角度は変わらず、`locks` に `contradiction` が残る
- [ ] 一時停止（`paused: true`）でも手の拘束が効く
- [ ] `unwrapDelta`、`angleAroundAxis`（S1-19 の資料のテストケース。こちらで先に作る場合）
### Playwright（`e2e/hand-rotation.spec.ts`）
準備: `two-gears.json` を読み込み、上から見下ろす視点（`setCamera`）にする。ドラッグの経路は、A の中心 `c`（`getLayout`）から半径 15 の、A の面上の点 `c + [15cos φ, 0, 15sin φ]` を `projectToScreen` したもの。φ を 0 → π/2 まで 10 段階で `mouse.move` する。
- [ ] 経路をドラッグして離す → A のシャフトの角度の変化が −π/2（`+X` から `+Z` へ回すのは +Y 軸まわりの負の向き。誤差 0.05 rad）。B のシャフトの角度の変化が +π/2。`getCamera()` は変わらない。`getSelection()` は変わらない
- [ ] φ = π/4 まで動かして止めた状態で、`expect.poll` で A の角度の変化が −π/4 に近づく（手に完全に追従）。このとき `getHand()` が A のシャフト。離したら `getHand()` が null
- [ ] 離した後、`getMotion().omegas` が 0（モーター無し）で、角度は離したときのまま
- [ ] 動かさずにクリック → `getSelection()` が `[A]` になり、角度は変わらない
- [ ] Alt を押しながら同じ経路 → 角度は変わらず、`getCamera()` が変わる
- [ ] `lock-opposed.json` → 最初は `locks` に `stalemate` がある。A をドラッグしている間は A のシャフトの角度が変わり、`locks` が空。離すと `locks` が戻り、ω が 0
- [ ] `one-root-motor.json`（S1-18 と同じもの。S1-18 より先にこのタスクをやるなら、ここで作る）で、A をモーターと逆向きに回す → 回している間 `backDriven` にそのモーター。離すと A のシャフトの ω が π に戻る
- [ ] `lock-triangle.json` → 読み込んだ時点で `getMotion().locks` に `reason: 'contradiction'` のロック（3 本のシャフト）がある。A をドラッグしても角度が変わらず、`getCamera()` も変わらない

## 人が手で確かめる項目
- つかんだ所が手にぴったりついてくる感覚がある（ずれや遅れがない）
- 斜めや真横に近い視点から回しても、回る向きが直感どおりで、飛ばない
- 速く回したり、描画領域の外までドラッグしたりしても破綻しない
