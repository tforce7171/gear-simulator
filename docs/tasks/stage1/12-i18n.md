# S1-12 日本語と英語の切り替えの仕組み

## 目的
画面の文字列をすべて辞書から引けるようにし、日本語と英語を切り替えられるようにする（要件 §11、design.md §8）。後続の UI タスクは、文字列を必ずここで作る `t()` 経由で出す。

## 範囲
- `ja` と `en` の辞書。`ja` のキーを正とし、`en` が同じキーをちょうど持つことを型で強制する
- 純粋な翻訳関数（キー → 文字列、`{name}` 形式の差し込み）
- 言語の初期値の決定（ブラウザの言語が `ja` で始まれば日本語、それ以外は英語）
- 実行時の現在の言語の保持、切り替え、切り替えの通知
- `document.title` と `<html lang>` を現在の言語に合わせる（このタスクで画面に出る唯一の文字列）

## 範囲外
- 言語を選ぶ UI と、設定としての localStorage への保存（S1-30）。保存された設定があればブラウザの言語より優先するのは S1-30 で配線する
- 画面の各部品の文字列そのもの（各 UI タスクが、必要なキーをそのタスクで辞書に足す）

## 作るもの
- `src/core/i18n/ja.ts`
  ```ts
  export const ja = {
    'app.title': '歯車シミュレーター',
    // キーは「領域.名前」のドット区切りの平らな文字列にする
  } as const;
  export type MessageKey = keyof typeof ja;
  ```
- `src/core/i18n/en.ts`
  ```ts
  export const en = {
    'app.title': 'Gear Simulator',
  } satisfies Record<MessageKey, string>; // 足りないキーも余分なキーも型エラーになる
  ```
- `src/core/i18n/index.ts`
  ```ts
  export type Lang = 'ja' | 'en';
  export type MessageParams = Readonly<Record<string, string | number>>;
  export function detectLanguage(browserLanguage: string | undefined): Lang;
  export function translate(lang: Lang, key: MessageKey, params?: MessageParams): string;
  export function placeholdersOf(message: string): string[]; // テストと検証用
  ```
  - `translate` は `{name}` を `params.name` で置き換える。`params` に無い差し込みはそのまま残す（例外にしない）
- `src/app/i18n.ts`（実行時の状態。DOM には触れない）
  ```ts
  export function t(key: MessageKey, params?: MessageParams): string;
  export function getLanguage(): Lang;
  export function setLanguage(lang: Lang): void;
  export function onLanguageChange(listener: (lang: Lang) => void): () => void; // 解除関数を返す
  ```
  - 起動時に `detectLanguage(navigator.language)` で初期値を決める
  - 将来、S1-30 で AppState.settings の言語と結び付ける。そのときこのモジュールの API は変えない
- `main.ts`（または app の組み立て）で、言語が変わるたびに `document.title = t('app.title')`、`document.documentElement.lang = lang` にする
- `__gearSim` に追加（design.md §10 の表のとおり）
  ```ts
  getLanguage(): Lang;
  setLanguage(lang: Lang): void;
  ```

## 受け入れ条件
- [ ] `en.ts` からキーを 1 つ消す、または余分なキーを足すと `tsc --noEmit` が失敗する
- [ ] `t('存在しないキー')` は型エラーになる
- [ ] ブラウザの言語が `ja-JP` なら日本語、`en-US` や `fr` なら英語で起動する
- [ ] `setLanguage` でタブの題名と `<html lang>` が切り替わる

## テストケース
### Vitest（`src/core/i18n/i18n.test.ts`）
- [ ] `detectLanguage('ja')` → `'ja'`、`'ja-JP'` → `'ja'`、`'JA-jp'` → `'ja'`（大文字小文字を区別しない）
- [ ] `detectLanguage('en-US')`、`'fr'`、`''`、`undefined` → `'en'`
- [ ] `translate('ja', 'app.title')` → `'歯車シミュレーター'`、`translate('en', 'app.title')` → `'Gear Simulator'`
- [ ] 差し込み: `{count}` を含むテスト用のキーで `translate(lang, key, { count: 3 })` が `3` を含む文字列を返す（テスト用のキーを辞書に足すのが嫌なら、差し込みの処理を内部関数に分けてそれを直接テストする）
- [ ] 足りない差し込みは `{name}` のまま残る
- [ ] すべてのキーについて、`ja` と `en` の値が空文字でない
- [ ] すべてのキーについて、`placeholdersOf(ja[key])` と `placeholdersOf(en[key])` が同じ集合になる
- [ ] 型のテスト（`tsc` で確かめる。テストファイルが tsconfig の対象に入っていること）
  - `// @ts-expect-error` を付けた `translate('ja', 'no.such.key')` の行がある
  - `expectTypeOf(en).toMatchTypeOf<Record<MessageKey, string>>()`
### Playwright（`e2e/i18n.spec.ts`）
- [ ] `test.use({ locale: 'ja-JP' })` で開く → `document.title` が `'歯車シミュレーター'`、`<html lang="ja">`、`__gearSim.getLanguage()` が `'ja'`
- [ ] `test.use({ locale: 'en-US' })` で開く → `document.title` が `'Gear Simulator'`、`<html lang="en">`
- [ ] `ja-JP` で開いて `__gearSim.setLanguage('en')` → `document.title` が英語に変わる。`setLanguage('ja')` で戻る
- [ ] コンソールエラーが 0 件（共通フィクスチャ）
